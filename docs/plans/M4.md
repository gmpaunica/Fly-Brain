**Goal:** Connect the fixed sensory-only spiking network to the fly through a
causal, deterministic motor decoder that runs exactly once per 20 ms world tick.

**Architecture:** A decoder converts complete motor-population spike counts to a
bounded `MotorCommand`. A neural controller accepts only `SensoryObservation`.
A closed-loop orchestrator owns timing: it samples the current pose, advances 20
one-millisecond neural steps, decodes, moves the world once, then publishes an
immutable tick snapshot. The existing manual simulation remains independent of
PyTorch and is selected explicitly in the app.

**Tech stack:** Python 3.12, CPU PyTorch 2.14, Pygame 2.6.1, pytest 9.1.1.

**Spec:** `docs/architecture.md` lines 100–110, `docs/BUILD_QUEUE.md` FB-04,
and the M4 acceptance section in `docs/reference/PROJECT_BRIEF.md`.

## Global constraints

- The neural controller receives only finite, nonnegative left/right odor
  concentrations. Coordinates, heading, source data, target bearing/distance,
  world objects, and precomputed steering never cross that boundary.
- The existing fixed graph, encoder, tonic current, one-millisecond neuron step,
  and 20-substep neural interval remain unchanged. There is no training.
- Screen coordinates use +x right, +y down, and positive turn clockwise/right.
- Rendering never advances world/neural state or consumes simulation randomness.
- Manual mode remains usable without importing PyTorch; neural mode is explicit
  and never combines held-key movement with network commands.
- Reset clears body/timing, neural voltage and pending spikes, decoder smoothing,
  accumulated frame time, and the last closed-loop snapshot while retaining the
  immutable odor source and fixed topology.
- No live brain panel, food success rule, reward, learning, checkpoint, or
  navigation-performance claim belongs to FB-04.

## Exact motor assumptions

The decoder uses all spikes accumulated in `NeuralActivity.spike_counts`, never
the last-substep boolean vector. For each ten-neuron motor group:

```text
raw(group) = clamp(sum(group spike counts) / 10, 0, 1)
raw_forward = raw(motor_forward)
raw_turn = raw(motor_right) - raw(motor_left)
smoothed = 0.5 * raw + 0.5 * previous_smoothed
command = MotorCommand(clamp(smoothed_forward, 0, 1),
                       clamp(smoothed_turn, -1, 1))
```

Thus an average of one spike per neuron in a 20 ms tick (50 Hz) is the arbitrary
full-scale activity reference; higher counts saturate. `motor_left` turns left
(negative) and `motor_right` turns right (positive). The fixed 0.5 exponential
smoothing coefficient is hand-written actuator scaffolding, not learned or
biologically measured. Reset restores both smoothed values to zero.

## Review focus

- Wrong-shaped, non-integer, negative, nonfinite, or non-CPU spike counts must be
  rejected before changing decoder smoothing state.
- A world tick that does not equal exactly 20 configured neural substeps must be
  rejected when the closed loop is constructed.
- Negative/nonfinite elapsed frame time must leave accumulator, world, neural,
  decoder, and snapshot state unchanged.
- Reset after partial accumulated time must reproduce the same tick snapshots
  and trajectory for the same body/network seeds.
- Importing and running the default manual app must not import PyTorch; the HUD
  and window title must clearly distinguish `MANUAL DEBUG` from `NEURAL CLOSED LOOP`.
