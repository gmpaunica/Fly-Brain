# simulation
FixedStepSimulation(arena: Arena, fly: Fly, dt: float = 0.02)
FixedStepSimulation.step(command: MotorCommand) -> bool  # one physics tick
FixedStepSimulation.advance(elapsed: float, command: MotorCommand) -> int  # ticks
FixedStepSimulation.reset(seed: int = 0) -> None
# Exposes arena, fly, tick_count; reset respawns and clears accumulator/tick_count.

# app
main(argv: list[str] | None = None) -> int

These signatures are the implementation target, not executable declarations. Dataclasses are sufficient; no abstract controller framework is needed yet. Use an immutable command. World state can be mutable, but drawing must only read it.

## 2. Kinematics and bounds

```python
import math
import pytest
from flybrain.world.fly import Fly, MotorCommand


def test_forward_motion_uses_seconds():
    fly = Fly(x=100.0, y=100.0)
    fly.step(MotorCommand(forward=1.0), 0.5)
    assert (fly.x, fly.y) == pytest.approx((150.0, 100.0))
    assert fly.forward_speed == pytest.approx(100.0)


def test_turn_happens_before_translation():
    fly = Fly(x=100.0, y=100.0)
    fly.step(MotorCommand(forward=1.0, turn=1.0), 0.5)
    assert fly.heading == pytest.approx(math.pi / 2)

```

## 3. Fixed-step simulation and replay

- [ ] Write a frame-partition test using a constant command. In `tests/test_simulation.py`:

```python
import pytest
from flybrain.world.arena import Arena
from flybrain.world.fly import Fly, MotorCommand
from flybrain.simulation import FixedStepSimulation


def test_frame_partitions_produce_the_same_ticks_and_pose():
    a = FixedStepSimulation(Arena(), Fly(100.0, 100.0))
    b = FixedStepSimulation(Arena(), Fly(100.0, 100.0))
    command = MotorCommand(forward=1.0, turn=0.25)
    assert a.advance(0.1, command) == 5
    assert sum(b.advance(t, command) for t in [0.01, 0.03, 0.06]) == 5
    assert a.tick_count == b.tick_count == 5
    assert (a.fly.x, a.fly.y, a.fly.heading) == pytest.approx(
        (b.fly.x, b.fly.y, b.fly.heading)
    )
```

- [ ] Confirm failure, then implement `step` and `advance`: accumulate elapsed time; consume complete 0.02-second ticks; retain the remainder. Use a documented tiny roundoff tolerance if needed, not rounding physical state. `step` advances exactly once without reading a clock. Validate dt/elapsed; dt must be positive and elapsed may be zero.
- [ ] Test no tick at 0.01 s and one tick after another 0.01 s. Test zero/invalid elapsed. Test reset clears a partial accumulator, body state and tick count.
- [ ] Replay a per-tick command schedule twice from the same seed and compare complete trajectories. Frame-partition equivalence applies when the command supplied for each consumed tick is the same; different keyboard polling schedules are not promised identical.
- [ ] Run simulation, arena and fly tests together. Rendering must not be imported by these modules.
